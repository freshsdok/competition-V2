## 推理与边界

1. 既有测试账号交集为空，因此 52030、52050 是另行筛选的候选，不能描述成原 60 账号名单已经覆盖获奖填报。团队资格及后续操作范围以主任务实际核验和授权为准，不由本报告扩张。
2. `READY_SOURCE_SNAPSHOT` 只说明查询时来源谱系和主体生命周期满足代码条件；原生入口仍需核对当前本人会话、Account/Subject、短期 intent 及实际办理权。`HOLD` 不能通过直接改账号/认领状态变成测试通过。
3. V2 保存要求正式、新近且达到 STRONG 的会话，并检查已有有效实名证据是否相容。历史相容性结果不表示卡号归属、银行验卡、发奖或到账；安全验证也不是后端强制“密码且短信”两因子组合。
4. V2 保存、向指定单位提供、V1 最终人工确认是三个独立事实。源码、单元测试、合成页面或预检 SQL 均不能替代这三个真实操作的结果。
5. V1 完成保持 `USER_CONFIRMED_COMPLETE` 的办理人声明含义。V1/V2 状态读回与最终写入不是跨库原子事务，且本轮未产生真实最终确认记录。
