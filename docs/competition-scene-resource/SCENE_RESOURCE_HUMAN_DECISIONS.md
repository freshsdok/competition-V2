# 大赛现场设备资源管理与预约人工确认事项

更新时间：2026-06-30

## 1. 已确认固定结论

以下结论作为后续开发依据：

- 不使用旧 `site_*` 表体系。
- 不新建独立现场系统。
- 继续使用 `competition_scene_*` 命名体系。
- 资源台账独立维护。
- 资源部署和预约时段配置嵌入“赛场安排”的“资源与预约”Tab。
- 不设计独立运维端。
- 不考虑运维人员独立操作。
- 运维相关只保留品牌型号、运维联系人、运维联系电话、是否需要运维确认。
- 资源状态包含启用、停用、维护中，不另设启用状态字段。
- 选手预约的是已部署到赛场安排、已开放时段的设备资源，不是资源台账。
- 本阶段不考虑最晚取消时间。
- 不修改旧报名、支付、成绩、证书主流程。
- 预约单位是设备，不是工位。
- 工位数用于容量展示和设备数计算。
- 必须有有效现场证件才能预约。
- 只允许 `schedule_target` 匹配对象预约。
- 非共享占用不允许同一 slot 追加预约。

## 2. 预约主体逻辑确认

旧规则已废弃：

- 不再要求团队比赛必须由队长预约。
- 不再校验队长身份。
- 不再用“团队预约流程”和“个人预约流程”两套逻辑开发。

新规则：

- 预约主体统一来自 `competition_scene_schedule_target`。
- 团队参赛时，队伍中任意有效参赛成员均可代表本队预约。
- 个人参赛时，个人本人可预约。
- 操作人只是 `operator_user_id`。
- 真正锁定的是 `reservation_subject`。
- 同一 `schedule_id` 下，同一 `reservation_subject` 只能存在一条未过期有效预约。
- 队伍中一人预约后，本队其他成员再次预约时，系统展示已有预约信息，并拒绝重复预约。

## 3. reservation subject 字段确认

预约记录表使用：

- `subject_type`：`TEAM` / `USER`。
- `subject_code`：团队时存 `team_code`，个人时存 `user_id` 或 target 引用。
- `team_code`：团队预约时冗余保存。
- `user_id`：个人预约时保存；团队预约时可冗余操作人。
- `operator_user_id`：实际操作人。

确认：

- 现有报名体系不存在稳定数字型 `teamId`。
- 第一阶段以 `team_code` 为准。
- 后端接口字段使用 `teamCode`。
- 不假设存在数字型 `teamId`。
- 新表不设计 `team_id` 字段。

## 4. 预约锁定规则确认

有效预约锁定范围：

```text
schedule_id + subject_type + subject_code
```

有效状态：

- `RESERVED`
- `CHECKED`

过期处理：

- 如果关联 slot 已过期，则查询时可显示过期。
- 已过期预约不再阻止后续新时段预约。
- 不做自动过期任务。
- 不自动修改数据库预约状态为 `EXPIRED`。
- 新预约校验时，应排除关联 slot 已过期的预约。

重复预约：

- 返回错误码 `ALREADY_RESERVED_BY_SUBJECT`。
- 同时返回 `existingReservation` 摘要。
- 前端展示已有预约信息。

## 5. 设备数计算确认

本阶段：

- 用户不能自由调整预约设备数。
- 预约设备数由后端自动计算。
- 团队预约设备数 = `ceil(参赛选手人数 / 每台设备工位数)`。
- 个人预约默认 1 台设备。
- 工位数用于展示和计算，不是预约单位。
- 预约单位始终是设备。
- 如果剩余设备数不足，则拒绝预约。

团队人数统计：

- 第一阶段只统计参赛选手。
- 不统计指导教师、带队老师、专家。
- 如现有报名表不能直接区分，则按 `schedule_target` 或报名成员角色过滤。

## 6. 个人比赛识别口径确认

个人/团队识别不再用于决定不同预约流程。

新的统一流程：

1. 识别主体。
2. 校验证件。
3. 查重预约。
4. 计算设备数。
5. 校验容量。
6. 创建预约。

识别结果：

- 如果 target 是团队，`subject_type = TEAM`。
- 如果 target 是个人，`subject_type = USER`。

## 7. 有效现场证件规则确认

保持：

- 必须有有效现场证件才能预约。
- 第一阶段有效判断为 `credential_status = EFFECTIVE` 且未过期。
- 如需冻结，未来在 `credential_status` 中扩展 `FROZEN`。
- 不新增独立冻结字段。

## 8. 现场核销确认

本阶段保留管理端核销接口。

现场核销方向：

- 现场管理员用小程序扫描参赛证签到后核销。
- 可复用已有 `sceneVerify` 二维码核验能力。
- 本阶段不加入复杂扫码核销流程。

## 9. 其他确认项

eventId：

- 系统中已存在大赛现场活动口径。
- 第一阶段可直接使用 `competition_series_id`，不用独立 event 表。

图片：

- 复用现有上传组件。
- 字段中保存可直接访问的 URL JSON 数组。

参数列表：

- 第一阶段使用键值对数组：

```json
[
  { "name": "GPU", "value": "RTX" },
  { "name": "内存", "value": "64GB" }
]
```

时段重叠：

- 第一阶段不允许同一 `schedule_resource_id` 下未删除时段时间重叠。
- 批量生成时遇到重叠则跳过。

暂停预约：

- 暂停只阻止新预约。
- 已有预约仍有效。
- 已有预约仍可取消和核销。

资源维护中：

- 资源台账改为 `MAINTENANCE` 后，不自动影响已发布布置。
- 管理员在资源与预约 Tab 手动暂停或关闭预约。

## 10. 上线前验收口径

必须能验证：

- 管理员可维护资源台账。
- 管理员可在赛场安排中布置资源。
- 管理员可批量生成预约时段。
- 管理员可发布/暂停/关闭预约。
- 用户只看到自己有资格预约的资源。
- 无有效现场证件不能预约。
- 不在 `schedule_target` 中不能预约。
- 团队任意有效参赛成员可代表本队预约。
- 同一 `schedule_id` 下本队已有预约后，其他成员再次预约时显示已有预约信息，并拒绝重复预约。
- 个人参赛者只能查看和预约自己的资源。
- 预约以设备为单位。
- 工位容量展示正确。
- 非共享占用不允许同一 slot 追加预约。
- 并发预约不超卖。
- `RESERVED` 可取消。
- `CHECKED/CANCELLED` 不可取消。
- 已过期预约不阻止后续新时段预约。

## 11. 错误码确认

新增：

- `ALREADY_RESERVED_BY_SUBJECT`：当前参赛主体已有有效预约。
- `SUBJECT_NOT_RESOLVED`：无法识别当前用户对应的参赛主体。
- `SUBJECT_MEMBER_INVALID`：当前用户不是该参赛主体有效成员。

保留：

- `NO_VALID_CREDENTIAL`
- `NOT_SCHEDULE_TARGET`
- `RESOURCE_NOT_OPEN`
- `SLOT_NOT_OPEN`
- `CAPACITY_NOT_ENOUGH`
- `EXCLUSIVE_SLOT_OCCUPIED`
- `DUPLICATE_RESERVATION`
- `RESERVATION_NOT_CANCELABLE`
- `IDEMPOTENCY_KEY_REQUIRED`

## 12. 仍需人工确认项

- 团队预约的取消权限是否允许任意有效参赛成员操作，还是只允许预约操作人或指定角色操作。
- 此处人工确认为：预约的取消权限是以“谁预约、谁取消”为原则。
## 13. 后续增强但本阶段不做

- 完整小程序扫码核销设备预约。
- 自动过期任务。
- 预约提醒。
- 预约导出。
- 按工位号精确分配。
- 更细的团队成员预约权限。
- 与现场大屏或调度看板联动。
- 设备异常临时停用和批量通知。
