# 大赛现场设备资源预约用户端界面计划

更新时间：2026-06-30

## 1. 用户端范围

本阶段用户端以小程序为主，PC 端后续可复用同一批接口。

用户端只做：

- 查看可预约的现场设备资源。
- 查看资源详情和可预约时段。
- 提交预约。
- 查看已有预约。
- 取消未核销预约。

不做：

- 资产信息展示。
- 运维操作。
- 运维确认。
- 最晚取消时间控制。

## 2. 新预约主体逻辑

用户端不再展示“队长预约”限制。

统一规则：

- 预约主体来自 `competition_scene_schedule_target`。
- 团队参赛时，队伍中任意有效参赛成员均可代表本队预约。
- 个人参赛时，个人本人可预约。
- 操作人只是当前登录用户。
- 系统真正锁定的是 `subjectType + subjectCode`。
- 同一 `scheduleId` 下同一 subject 只能有一条未过期有效预约。

团队中一人预约后：

- 本队其他成员再次进入预约时，页面展示已有预约信息。
- 提交预约时后端返回 `ALREADY_RESERVED_BY_SUBJECT`。
- 前端展示 `existingReservation`，并拒绝重复预约。

## 3. 入口建议

入口：

- 我的赛事。
- 现场服务。
- 设备预约。

进入前置提示：

- 无法识别参赛主体：提示“暂未识别到你在该赛场安排中的参赛信息。”
- 不是有效成员：提示“当前账号不是该参赛主体有效成员。”
- 无有效现场证件：提示“暂未找到有效现场证件，请先确认参赛证已生成。”

## 4. 可预约资源列表

接口：

`GET /competition/userCompetition/sceneResource/bookableList`

资源卡展示：

- 资源名称。
- 资源类型。
- 品牌型号。
- 部署位置。
- 剩余设备数。
- 剩余工位数。
- 每台设备工位数。
- 下一可预约时段。
- 当前预约主体：团队/个人。
- 是否已有预约。

已有预约时展示：

- 已预约资源。
- 预约时段。
- 预约设备数。
- 覆盖工位数。
- 操作人。
- 状态。

## 5. 资源详情页

接口：

`GET /competition/userCompetition/sceneResource/{scheduleResourceId}`

展示：

- 资源名称。
- 资源类型。
- 品牌型号。
- 部署位置。
- 安全须知。
- 注意事项。
- 主要参数。
- 使用说明。
- 设备图片。
- 每台设备工位数。
- 当前预约主体。
- 后端计算的预约设备数。
- 可覆盖工位数。
- 已有预约摘要。
- 可预约时段。

说明：

- 设备数由后端计算。
- 用户不能自由调整预约设备数。
- 工位数只做展示和计算，不是预约单位。

## 6. 时段列表

接口：

`GET /competition/userCompetition/sceneResourceSlot/list?scheduleResourceId=`

字段：

- 开始时间。
- 结束时间。
- 剩余设备数。
- 剩余工位数。
- 每台设备工位数。
- 系统计算预约设备数。
- 可覆盖工位数。
- 是否可预约。
- 不可预约原因。
- 已有预约摘要。

不可预约原因示例：

- 已有未过期预约。
- 资源未开放。
- 时段未开放。
- 剩余设备不足。
- 非共享时段已被占用。
- 无有效现场证件。

## 7. 预约确认页

展示：

- 预约主体：团队 / 个人。
- 主体名称或编码。
- 当前操作人。
- 资源名称。
- 部署位置。
- 预约时段。
- 每台设备工位数。
- 系统计算预约设备数。
- 可覆盖工位数。
- 剩余设备数。
- 剩余工位数。

团队参赛：

- 展示团队名称/团队编号。
- 展示参赛选手人数。
- 设备数 = `ceil(参赛选手人数 / 每台设备工位数)`。
- 不展示队长校验。
- 不限制只有队长可预约。

个人参赛：

- 展示个人姓名。
- 默认预约 1 台设备。

提交接口：

`POST /competition/userCompetition/sceneResourceReservation`

请求：

```json
{
  "slotId": 1,
  "idempotencyKey": "client-generated-uuid"
}
```

不传：

- `subjectType`
- `subjectCode`
- `teamId`
- `teamCode`
- `reservedDeviceCount`

## 8. 已有预约提示

当后端返回：

- `ALREADY_RESERVED_BY_SUBJECT`

前端展示：

- 已有预约标题。
- 资源名称。
- 部署位置。
- 预约时段。
- 预约设备数。
- 覆盖工位数。
- 实际操作人。
- 核销状态。

建议文案：

> 当前参赛主体已有设备预约，无需重复预约。请按以下预约信息到场使用。

## 9. 我的预约

接口：

`GET /competition/userCompetition/sceneResourceReservation/myList`

团队 subject：

- 团队任意有效参赛成员可查看本队预约。

个人 subject：

- 个人参赛者只能查看自己的预约。

列表字段：

- 资源名称。
- 部署位置。
- 预约时段。
- 是否已过期。
- 预约主体。
- 操作人。
- 预约设备数。
- 覆盖工位数。
- 预约状态。
- 核销状态。
- 操作。

## 10. 取消预约

接口：

`POST /competition/userCompetition/sceneResourceReservation/cancel`

请求：

```json
{
  "reservationId": 1,
  "cancelReason": "计划调整"
}
```

规则：

- `RESERVED` 且未核销可取消。
- `CHECKED/CANCELLED` 不可取消。
- 第一阶段建议团队任意有效参赛成员可取消本队未核销预约。
- 团队取消权限仍建议业务确认；若需限制，可后续收紧为预约操作人或指定角色。
- 个人参赛者只能取消自己的未核销预约。

## 11. 过期展示

本阶段不做自动过期任务。

页面展示：

- 根据预约关联时段 `endTime` 判断是否已过期。
- 已过期预约在列表中显示“已过期”。
- 已过期预约不阻止同一主体预约后续新时段。

## 12. 用户端验收

必须能验证：

- 团队任意有效参赛成员可代表本队预约。
- 同一赛场安排下本队已有预约后，其他成员再次预约会看到已有预约信息，并被拒绝重复预约。
- 个人参赛者只能查看和预约自己的资源。
- 用户不能手动调整预约设备数。
- 无有效现场证件不能预约。
- 不在 `schedule_target` 中不能预约。
- 剩余设备不足不能预约。
- 非共享时段已占用不能预约。
