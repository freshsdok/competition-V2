## 2. 一句话功能定义

V1“赛证互通”允许运营人员配置“用户已持有的源证书”到“可申请的目标证书”的兑换规则，系统核验用户证书、计算差额费用、创建兑换申请和支付订单；同时提供申请管理、证书发放/导入、我的证书、证书查询、预览与批量下载等配套能力。其中“用户已持有的源证书”系指整个平台中任何租户或者组织定义过的可以被其他人使用的具有公共属性的证书。

从用户视角，主链路是：

```text
浏览互通规则
→ 阅读申请说明
→ 登录并完成实名认证
→ 系统核验源证书和持有年限
→ 选择目标证书
→ 计算兑换费用
→ 防重复校验
→ 创建兑换申请和支付订单
→ 支付结果回写申请
→ 后续获得并查看已经获得的目标证书
```

## 3. 功能边界

### 3.1 核心“赛证互通”能力

1. 源证书与目标证书配置。
2. 互通规则草稿、发布、撤销、排序、首页展示。
3. 用户源证书匹配与持有年限判断。
4. 源证书组合条件（且/或）。
5. 证书分值和差额费用计算。
6. 兑换申请、重复申请检查和支付下单。
7. 支付、发票状态回写。
8. 用户与运营端申请查询、筛选、导出。
9. 为了做好赛证互通，需要有对各类证书的分值定义，以便利用分值计算应支付的费用，这里的分值不是证书自身的属性，而是运营人员配置的，可以根据其兑换的边界条件自行在配置规则中配置，这部分能力的设计也可以根据实际设计需求由AI提出更好的方案。
### 3.2 同一菜单下的相邻能力

以下能力与赛证互通共享证书数据或页面入口，但不是“兑换规则”本身：

- 赛事获奖证书配置和批量颁发；
- 历史/外部证书导入；
- 我的证书聚合展示；
- 公共证书查询；
- 负责人名下学生证书预览、缺图补偿和异步打包下载；
- 证书图片缓存同步。

以上功能作为V1的能力参考，如果迁移到 V2 时必须分别确认 Fact Owner，不能继续作为一个“大证书模块”整体搬迁。

## 5. V1 前端功能拆解

### 5.1 PC 用户端至少可见

| 互通规则列表 | 关键词搜索、分页、展示规则名称、源证书组合及发布时间 |
| 申请说明 | 无登录查看规则说明；申请前要求登录和实名信息 |
| 证书兑换明细  | 展示源证书满足情况、目标证书、费用并发起支付 |
| 我的证书 | 聚合内部与历史证书；支持负责人证书筛选、预览与异步导出 |
| 证书查询 | 按人员、单位或证书编号查询赛事证书 |

关键用户交互：

- “且”规则要求所有源证书均满足；“或”规则允许选择一个符合条件的源证书。
- 目标证书有多项时，根据用户选择生成对应的订单和待支付记录
- 页面根据后端计算结果显示“满足条件/无此证书/拥有年限不足等约束性规则的反馈以及 可兑换/不可兑换的结论”。
- 支付前先调用重复订单检查，再弹出源证书、目标证书和金额确认框。
- 下单成功后跳转到个人支付页面。

### 7.2 费用计算
采用：

```text
源证书总分 = 所选源证书分值之和
目标证书总分 = 所选目标证书分值之和
总费用 = max(目标证书总分 - 源证书总分, 0)
单个目标费用 = 目标证书分值 - 源证书总分
```

代码把“分值”直接作为金额差使用，没有独立的价格版本、币种、计价策略快照或舍入策略。
