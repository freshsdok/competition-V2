## 重点流程说明

### 现场证件 / grant / 扫码
证件是现场主体快照，grant 是能力授权事实，operation_state 应成为“某主体在某赛程某动作是否完成”的当前事实，operation_log 应只承担审计流水。当前源码和表结构同时暴露多类状态字段，后续应避免业务判断从 log 或展示字段反推事实。

### 资源预约
预约创建至少涉及预约主体识别、slot/schedule_resource 查询、容量检查、active_reservation_key/idempotency_key、预约插入和 slot 容量更新。该流程应以数据库唯一键和条件更新兜底，应用层返回幂等结果而不是暴露唯一键异常。

### 评审
评审模块已有一组单测，说明近期建设较集中；但分配、材料、评分、秘书控制台之间需要明确 session/object/submission/score/result 的事实源，避免秘书操作和专家评分状态交叉覆盖。
