# 银行资料填报 · 引导式原型 A

状态：用户已确认样式与交互，并于2026-09-14按此接入 V1/V2 页面。此文件仍是独立合成原型；真实实现及验证范围见 [接入说明](../../team-collection-guided-20260914.md)。

打开 `bank-collection.html`，可直接体验。所有数据均为示例，短信、密码验证、保存、提供和团队完成都在页面内模拟；不会请求真实接口，不使用浏览器持久化。

## 本版方案

1. 三步结果分别为“填写银行卡 → 确认提供 → 完成填报”。保存与提供不合并，避免丢失指定接收方的明确同意。
2. 将长说明收进“填报须知”、权限范围收进“谁可以使用这些资料？”，将 CNAPS 收进选填区域。
3. 填写阶段只突出“保存并继续”；安全验证完成后继续保存，取消时保留草稿。
4. 保存后展示脱敏摘要，直接展开单位选择与同意复选框。切换单位会清空同意，不自动选择或自动提供。
5. 提供成功后自动出现一次 Tour，高亮顶部“我已完成填报”。收起引导仍保留“待最终确认”；用户可重新打开引导。
6. “我已完成填报”本身作为办理人的明确最终确认，不再重复弹出确认框；仅收到完成操作成功结果后展示完成页。

## 体验方式

- 默认已填入示例，点击“保存并继续”体验完整流程。
- 短信演示：获取验证码后输入 `246810`；密码演示可输入任意非空文本。
- 点击原型上方“直接看最后一步”直接查看 Tour。
- 点击“重新体验”重置演示状态。
- 对话内的设计调节支持比较“聚光漫游 / 轻提示浮层”和表单间距；独立 HTML 使用默认样式。

## 接入前需要确认的边界

- 原型把 V1 外层状态与 V2 保存、提供结果统一展示，当前项目尚无本原型所用的可靠跨 iframe 结果联动。接入时必须核验当前办理人、团队与本次操作结果，不能仅凭任意 postMessage 或本地状态解锁最终完成。
- 页面重开、资料版本冲突、单位变化、入口过期后，需要重新读取真实状态；原型不代表上述后端能力已实现。
- 完成状态继续表示办理人确认，不能解释为已完成发奖、银行验卡或到账。
- 现有团队锁作用于办理入口；已签发入口不会因人工完成或释放立即吊销。原型没有改变这个边界。
- “更多操作”仅示意次要操作的收纳位置，不执行刷新、名额释放或更换办理人。
