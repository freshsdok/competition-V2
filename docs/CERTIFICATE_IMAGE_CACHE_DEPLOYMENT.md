# 证书图片缓存与导出部署说明

## 部署顺序

1. 先执行 `db/migration/20260825_certificate_image_cache.sql`。脚本可重复执行，会创建缓存、同步运行、异步导出三张表，并新增“证书图片同步”菜单及四项权限。
2. 部署文件服务 API、比赛服务、Admin 和 PC 前端。
3. 确认比赛服务与所有实例连接同一个 Redis；否则无法实现跨实例全局限流和任务互斥。
4. 确认文件服务使用私有 OSS/MinIO Bucket，并允许比赛服务调用上传、预签名、流式打包和删除接口。
5. 在 Admin 的“证书图片同步”页核对“应同步总数”，再手动启动首次全量同步。首次同步完成并核对失败清单前，不建议向全部负责人开放下载入口。

当前仓库中 `/oss` 这组上传、预签名、打包和删除端点由阿里云 OSS 实现，已统一使用 `OSSConfig`
的 endpoint、Bucket 和密钥。如生产实际切换为 MinIO，必须先为同一组内部端点提供等价实现并完成联调，
不能只替换配置后直接上线。

文件服务历史打包代码中曾存在源码密钥兜底，本次已删除。该凭据应按“已暴露”处理，上线前在 OSS 控制台轮换，
并仅通过配置中心/密钥管理服务注入新凭据。

## 可配置项

配置中心可覆盖以下属性；未配置时使用右侧默认值：

```yaml
competition:
  certificate:
    image:
      requests-per-second: 1
      sync-cron: "0 0 0 * * ?"
      retry-delay-1-ms: 5000
      retry-delay-2-ms: 30000
      retry-delay-3-ms: 120000
      failure-cooldown-hours: 6
      export-clean-cron: "0 20 * * * ?"
```

定时表达式统一按 `Asia/Shanghai` 执行。ZIP 任务有效期为 24 小时；每次下载时后端重新签发短时 OSS 地址。

## 上线核对

- Admin 统计总数应与负责人有权导出的不重复证书编号数一致。
- 外部查询必须只从比赛服务发出，旧 `guidedPackage` 接口应返回“已废弃”。
- 随机抽查缓存记录的对象键、文件大小和 SHA-256，并确认对象无法匿名访问。
- 用不同负责人账号验证分页、筛选、跨页勾选、预览、全部导出及越权证书编号拦截。
- 多实例部署时，同时启动手动任务和用户预览，确认外部查询日志仍满足配置的全局频率。
- 执行菜单 SQL 后管理员需退出重新登录以刷新菜单缓存；脚本只自动授权 `role_key = 'admin'`。
