# Review Engine V1.0 已知问题与未来规划

## 1. 当前已知限制

### 1.1 架构与复用

- Review Engine 仍内嵌在 `teaching-competition` 服务，尚不能独立部署。
- Competition 与 FileTask 适配代码集中在 `ReviewObjectServiceImpl`，没有统一的 `BusinessAdapter` SPI、注册表或幂等协议。
- 导入逻辑直接依赖竞赛 Mapper、领域对象和文件任务远程 DTO，新增业务源需要修改核心 Service。
- 数据表没有数据库外键，数据完整性主要依赖应用层校验；清理和迁移时需额外核对孤儿记录。

### 1.2 评审能力

- AI 评审辅助：规划能力 / 未实现。
- 自动专家匹配与推荐：规划能力 / 未实现；当前为人工单条或笛卡尔积批量分配。
- 复杂回避规则（同单位、利益冲突、历史合作等）：规划能力 / 未实现。
- 专家负载上限虽有 `reviewer_profile.max_task_count` 字段，但未形成完整自动分配约束。
- 多轮结果自动承接、晋级与自动流转：规划能力 / 未实现。
- 动态表单只覆盖评分指标和对象 `extra_data`；通用填报表单设计器：规划能力 / 未完全实现。

### 1.3 权限与接口

- Controller 权限码与活动内角色是两套机制；除 admin 外，迁移脚本没有自动配置 REVIEWER、SECRETARY、OBJECT_OWNER 的系统角色权限。
- 秘书扫码复用对象管理的 `object:query` 权限，存在角色授权耦合。
- `/review/record/draft`、`/review/record/submit`、`/review/record/my-list` 仍保留路由但运行时固定报错，是兼容性占位接口；客户端不应调用。
- 管理接口大多依赖权限码但没有统一的活动级数据范围过滤；非超级管理员的跨活动隔离需要单独验证。
- 普通用户没有公共结果查询接口；当前仅填报授权用户可查自己对象的已发布结果。

### 1.4 状态与一致性

- 部分状态存在于枚举但没有完整专用流转接口，例如活动/轮次的全部生命周期、`WITHDRAW_REJECTED`、场次暂停/结束。
- 撤回驳回当前直接回到 `SUBMITTED`，不会落库 `WITHDRAW_REJECTED`。
- 结果生成允许在部分专家已提交时计算当前平均分并给出告警；若业务要求“全部完成才可生成”，需要策略化。
- 排名使用顺序排名，未处理同分并列名次。
- 结果的 `calculated_grade` 当前没有通用等级计算策略，主要汇总 `calculated_score` 与排名。
- 主要表之间缺少数据库级唯一约束的场景仍需服务层保证，例如同一场次对象的重复关系由应用校验。

### 1.5 文件与现场

- Office 在线预览依赖 LibreOffice 和本地文件路径配置；不支持的格式会要求下载。
- 文件 URL、来源路径和本地存储耦合，独立部署前需要抽象 File Storage Provider。
- 专家现场页面通过前端 3 秒轮询刷新，没有 WebSocket/SSE 推送；大量并发场次需评估数据库与网关压力。
- 摄像头扫码依赖浏览器 BarcodeDetector 能力，失败时退化为手工输入证件编号。
- 场次切换依赖应用事务，没有跨节点事件总线；多秘书并发操作需要进一步做乐观锁/幂等设计。

### 1.6 测试与可运维性

- 扫描范围内未发现覆盖完整评审主流程的自动化集成测试、权限回归测试和并发测试。
- 迁移脚本分阶段演进，旧测试库的 `review_record` 可能与新库结构存在兼容差异，部署前应做 schema diff。
- 缺少面向评审引擎的指标体系，例如任务提交率、轮询 QPS、评分耗时、结果重算次数和导入失败率。

## 2. 后续规划

### 2.1 Business Adapter Framework

- 定义 `BusinessSourceAdapter`、预览模型、导入模型和能力声明；
- 按 `source_module + source_biz_type` 注册 Adapter；
- 将 Competition、FileTask 移出核心 Service；
- 建立幂等键、版本号、差量同步、失败重试和对账接口；
- 支持结果回写来源业务。

### 2.2 AI 评审辅助

- 材料摘要、合规性检查和评分项证据定位；
- 只提供建议，不自动写专家评分；
- 保存模型、提示词、引用证据和专家采纳记录；
- 对敏感材料实施数据分级、脱敏和审计。

### 2.3 专家推荐与回避

- 基于学科、分类、关键词和历史评分质量推荐专家；
- 将 `max_task_count` 纳入负载均衡；
- 支持单位、项目关系、黑白名单等可配置回避规则；
- 自动分配结果必须允许人工预览与确认。

### 2.4 数据分析

- 活动、轮次、专家、对象多维分析；
- 评分离散度、异常分、完成时效与一致性分析；
- 现场进度、候场时长和任务拥塞监控；
- 可审计的数据导出和脱敏视图。

### 2.5 多轮自动流转

- 轮次状态机和启动/结束专用接口；
- 依据排名、阈值或结论自动生成下一轮对象；
- 跨轮规则快照、任务继承和结果合并；
- 失败补偿、人工干预与完整事件日志。

### 2.6 独立部署

- 抽离认证用户上下文、文件服务、通知服务和审计服务；
- 建立独立 schema、版本化 OpenAPI 和事件协议；
- 增加幂等、乐观锁、限流、缓存与异步结果计算；
- 补齐单元、集成、契约、权限、性能和迁移测试。
